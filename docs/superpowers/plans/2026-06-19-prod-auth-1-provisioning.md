# Production Auth — Plan A: Provisioning & Identity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the signup FK gap at its source — a DB trigger provisions a `public.users` row for every `auth.users` insert (real and anonymous) — and lock in the identity contract `users.id == supabase_id == auth.uid()`.

**Architecture:** A `SECURITY DEFINER` `handle_new_user()` trigger (`AFTER INSERT ON auth.users`) creates the `public.users` row with `id = supabase_id = NEW.id`; a companion `AFTER UPDATE OF email, is_anonymous` trigger syncs anonymous→real upgrades. `public.users.email` becomes nullable and gains `is_anonymous`; user-owned FKs get `ON DELETE CASCADE`. The app layer is reduced to a cheap existence assertion (loud 500 if the row is missing — no self-heal). All DDL is hand-authored SQL in `packages/db/migrations/` (Drizzle is the sole migration authority); GoTrue settings are out of scope (Plan C / Spec 1 `config.toml`).

**Tech Stack:** Drizzle ORM + drizzle-kit, hand-authored Postgres SQL migrations, NestJS (api), Vitest + Testcontainers (`@autodidact/test-support`), Supabase CLI local stack (real `auth.users`).

**Source spec:** `docs/superpowers/specs/2026-06-18-production-auth-design.md` (Spec 2). This is **Plan A of 3** (B = anonymous mobile/worker; C = Data-API lockdown + hardening).

## Global Constraints

- **Drizzle is the sole migration authority.** All schema/DDL goes through `packages/db/migrations/`. **Never** create `supabase/migrations/`, **never** run `supabase migration new` / `supabase db diff` / `supabase db push`. (`packages/db/CLAUDE.md`.)
- **Schema column changes** (nullable/new column) are generated by `drizzle-kit` (`pnpm db:generate:dev`); **everything else** (triggers, functions, helper, cascade FKs if drizzle won't emit them) is **hand-authored SQL** following the `0003_rls.sql` / `0004_rls_fixes.sql` pattern, registered in `packages/db/migrations/meta/_journal.json`.
- **Identity contract (D1):** `users.id == users.supabase_id == auth.uid()` (the JWT `sub`). The trigger enforces it; never generate `users.id` independently again.
- **All `SECURITY DEFINER` functions** must be defined with `SET search_path = ''` and **fully schema-qualified** names (`public.users`, `auth.users`, …) — Supabase search-path-attack hardening.
- **Env var names** stay `SUPABASE_PUBLISHABLE_KEY` / `SUPABASE_SECRET_KEY`.
- **Local stack ports are remapped +1000** (Spec 1 deviation): DB `127.0.0.1:55322`, API `55321`. Local `DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:55322/postgres`.
- **This shell exports stale `DATABASE_URL`/`SUPABASE_URL`/`QUEUE_PROVIDER`** that shadow `.env.dev` (see `project_local_dev_known_issues`). For any command that must hit the local stack, override explicitly: `env DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:55322/postgres …`.
- **No self-heal at the API** (1c): a missing `public.users` row is a trigger failure → surface a loud 500, do not upsert.
- **Prod project = `cbzdsoojfhpsexuyeyxt`** (confirmed). Migrations apply to local **and** prod (this plan ends with a reviewed prod apply).

Create `packages/db/migrations/0007_auth_provisioning.sql`:

```sql
-- Hybrid provisioning (Spec 2, D2'/D6/D7). All SECURITY DEFINER functions are
-- hardened: SET search_path = '' + fully schema-qualified names.
-- Idempotent: safe to re-apply (CREATE OR REPLACE + DROP TRIGGER IF EXISTS).

-- is_anonymous() RLS helper (D7) — belt-and-suspenders; app reads the column.
CREATE OR REPLACE FUNCTION public.is_anonymous()
  RETURNS boolean LANGUAGE sql STABLE
  SET search_path = ''
  AS $$ SELECT COALESCE((auth.jwt() -> 'is_anonymous')::boolean, false) $$;

-- handle_new_user: provision public.users for every new auth.users row.
CREATE OR REPLACE FUNCTION public.handle_new_user()
  RETURNS trigger LANGUAGE plpgsql SECURITY DEFINER
  SET search_path = ''
  AS $$
  BEGIN
    INSERT INTO public.users (id, supabase_id, email, is_anonymous)
    VALUES (NEW.id, NEW.id, NEW.email, COALESCE(NEW.is_anonymous, false))
    ON CONFLICT (id) DO NOTHING;
    RETURN NEW;
  END;
  $$;

DROP TRIGGER IF EXISTS on_auth_user_created ON auth.users;
CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();

-- sync_user_from_auth: keep email/is_anonymous in sync on anon→real upgrade
-- (an UPDATE of auth.users, not an INSERT — the insert trigger won't fire).
CREATE OR REPLACE FUNCTION public.sync_user_from_auth()
  RETURNS trigger LANGUAGE plpgsql SECURITY DEFINER
  SET search_path = ''
  AS $$
  BEGIN
    UPDATE public.users
       SET email = NEW.email,
           is_anonymous = COALESCE(NEW.is_anonymous, false),
           updated_at = now()
     WHERE id = NEW.id;
    RETURN NEW;
  END;
  $$;

DROP TRIGGER IF EXISTS on_auth_user_updated ON auth.users;
CREATE TRIGGER on_auth_user_updated
  AFTER UPDATE OF email, is_anonymous ON auth.users
  FOR EACH ROW EXECUTE FUNCTION public.sync_user_from_auth();
```

- [ ] **Step 3: Implement the service**

Create `services/api/src/modules/provisioning/provisioning.service.ts`:

```typescript
import { Injectable, InternalServerErrorException } from '@nestjs/common';
import { getDb, users } from '@autodidact/db';
import { eq } from 'drizzle-orm';

@Injectable()
export class ProvisioningService {
  // Existence assertion only — the DB trigger (handle_new_user) provisions the
  // row. A missing row means the trigger failed; surface a loud 500, never
  // self-heal (Spec 2, 1c). This is the seam Spec 3 extends with onboarding.
  async ensureProvisioned(userId: string): Promise<void> {
    const db = getDb();
    const rows = await db.select({ id: users.id }).from(users).where(eq(users.id, userId)).limit(1);
    if (rows.length === 0) {
      throw new InternalServerErrorException(
        `User ${userId} is not provisioned — the handle_new_user trigger did not run. Fix the trigger; do not self-heal.`,
      );
    }
  }
}
```
